AI Agents Are Powerful. Who Authorizes Their Actions?

A production agent needs tool permissions, transaction boundaries, evidence and a human approval process for risky operations.

Ahmed Elkholy · 23 October 2026 · Engineering analysis with references

An agent is not an administrator

Agents make plans, browse data and call tools. That capability creates risk when a retrieved webpage, an email or a customer attachment includes malicious instructions. OWASP's October 2026 coverage of agentic AI incidents emphasizes how harmful actions can occur while an agent pursues an otherwise legitimate goal. Treat external content as untrusted data, never as permission to invoke sensitive tools.

Four boundaries worth enforcing

First, scope data access to the signed-in user and tenant. Second, use a separate tool allow-list per workflow; a sales assistant should not have a payroll export tool. Third, require a structured proposal and human approval for refunds, transfers, deletion and outbound bulk messaging. Fourth, apply deterministic server-side validation after approval. The language model never has the final word on authorization.

Recover from partial outcomes

Suppose an agent requests an order refund and the provider times out. Retrying blindly can create duplicate effects. Store an operation claim, a stable idempotency key and provider references; reconcile the outcome before marking it failed or completed. Preserve evidence without exposing customer secrets in logs. For bulk actions, use dry-run previews, quotas, an audit trail and a safe pause mechanism.

Prove boundaries with tests

Test prompt injection in retrieved documents, unexpected tool arguments, cross-tenant IDs, revoked permissions and delayed third-party callbacks. Report blocked attempts, approved actions, false positives and time-to-recover. Strong agents are not those that can do everything: they are those that can only do the right things under observable controls.
